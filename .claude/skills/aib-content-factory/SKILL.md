# aib-content-factory

aib.vote 홍보 콘텐츠를 **한 번의 실행 = 하루치 콘텐츠 배치**로 뽑아내는 스킬.
핵심 철학: **하나의 좋은 비교 주제 → 여러 포맷·채널로 재활용**(원자 콘텐츠 유닛).
매번 새 아이디어를 짜는 게 아니라, 앵커 주제 1개를 여러 형태로 파생시켜 배포 효율을 극대화한다.

> **코드로 자동화하려는 경우:** 이 수순을 앱(Next.js + Remotion)에 구현·자동화하는 설계 지시서는 `AUTOMATION.md`를 참조한다. 이 스킬 문서는 "무엇을/어떤 순서로"를, AUTOMATION.md는 "어떻게 코드화하고 개입을 줄이는지"를 다룬다.

## 제품 컨텍스트 (콘텐츠의 근거)

aib.vote는 AI 모델을 1:1로 비교·투표하게 해주는 플랫폼이다. 탭 구성: 텍스트 / 이미지 / 거짓말 / 속도.
- 콘텐츠 소재는 **aib.vote의 실제 비교 결과**에서 나온다(사용자가 캡처/결과를 붙여넣음). 새로 지어내지 않는다 — 진짜 결과가 곧 제품 데모다.
- 모든 콘텐츠 끝에는 항상 `직접 투표해보기 → aib.vote` CTA를 붙여 트래픽 루프를 닫는다.

## 확정된 동작 규칙 (이 스킬의 계약)

1. **주제 선정 = 반자동.** 트렌드에서 후보 3개를 추천하고, 사용자가 택1한다. 스킬이 임의로 확정하지 않는다.
2. **콘텐츠 유형 = 3종, 되는 것만(A안).** 한 주제가 3종을 다 지원하지 못할 때가 많으므로, 그 주제가 성립시키는 유형만 만든다. 못 채운 유형은 다음 실행에서 로테이션으로 채운다. **억지로 안 맞는 앵글을 끼워넣지 않는다.**
3. **포맷 = 스킬이 추천, 사용자가 확정.** 주제 성격에 따라 기본 포맷을 체크된 상태로 제시하되, 최종 선택(추가·제거·교체)은 항상 사용자가 한다. 추천은 기본값일 뿐 강제가 아니다.
4. **소재 = 수동 붙여넣기.** aib.vote 결과/캡처는 사용자가 붙여넣는다. 스킬이 자동으로 가져오지 않는다.
5. **글전용은 항상 병행.** 제작비 0이므로 어떤 주제든 커뮤니티·스레드 직행 텍스트 버전은 무조건 함께 뽑는다.
6. **각 선택 단계에서 멈춘다.** 주제 택1, 포맷 확정, 소재 붙여넣기 — 이 세 지점에서는 사용자 입력을 기다린다. 앞서 나가지 않는다.

## 실행 흐름

### STEP 1 · 주제 후보 추천 [반자동 → 사용자 택1]

트렌드를 **6개 카테고리에서** 수집해 스코어링하고 후보 **3개**를 제시한다.

**핵심 발상: 카테고리 = 소재의 출처, aib.vote = 비교 장치.**
AI 뉴스에만 갇히지 않는다. 어떤 카테고리의 화제든 **"이 주제를 여러 AI에게 물어보면?"** 형태의 aib.vote 비교 프롬프트로 변환하면 콘텐츠가 된다. 일반 대중 화제일수록 잠재 도달이 크다.
- 예) 경제: "환율 급등, 어느 AI가 방향을 맞혔나" / 사회: "이 논쟁적 이슈, GPT vs Claude 정반대 답" / 생활문화: "요즘 뜨는 이 밈, AI들은 알고 있을까"

**6개 수집 카테고리** (매 실행 시 되도록 여러 카테고리에서 후보를 고루 뽑는다):
1. **AI관련** — 모델 출시·정책·화제 (제품과 가장 직접적)
2. **경제** — 환율·주가·금리·부동산 등 (사실형 → 거짓말·속도 앵글 강함)
3. **사회** — 논쟁적 이슈·사건 (견해 갈림 → 의견 대립 앵글 강함)
4. **생활/문화** — 밈·트렌드·연예·스포츠 화제 (친숙·바이럴성 높음)
5. **IT/과학** — 신기술·연구·제품 (오픈웨이트·기술 앵글 연결 쉬움)
6. **세계** — 국제 뉴스·해외 화제 (해외 채널·Reddit 확장에 유리)

**수집 방법** (가능한 소스부터; 전용 API가 없으면 web_search로 카테고리별 최신 화제를 조회):
- **최근 48시간 우선.** 기본적으로 어제·오늘(약 2일 이내) 화제만 후보로 올린다. 트렌드는 빨리 식으므로, 신선도가 곧 경쟁력이다. web_search 시 날짜를 넣고("2026년 N월 N일"), 결과의 "며칠 전/시간 전" 표기로 48시간 이내를 우선 필터한다.
- 48시간 내에 마땅한 화제가 없는 카테고리는 억지로 채우지 말고 건너뛴다. 단, 최소 3개 후보를 확보하기 위해 부득이하면 최근 1주로 범위를 넓히되, 그 후보에는 "(다소 오래됨)"을 표시한다.
- 각 카테고리를 web_search로 "오늘/이번주 화제" 조회 → 신선도(며칠 전)·언급 빈도로 상위 화제 추림
- (연결돼 있으면) 유튜브 급상승·네이버 랭킹뉴스·Reddit hot을 해당 카테고리에 매핑
- 각 카테고리에서 화제성 높은 것 1~2개씩 후보 풀 구성 → 그중 스코어링 상위 3개 최종 선정

**3중 스코어링** (각 후보를 상◎·중○·하△로 평가):
- **트렌드**: 지금 사람들이 찾고 보는 주제인가 (신선도·언급 빈도 근거로 판단, 주관 판단임을 명시)
- **제품적합**: aib.vote 비교 프롬프트로 흥미롭게 변환되는가
- **후킹**: 놀라운 반전·논쟁이 있는가

카테고리가 서로 다르게 최소 2개 이상 섞이도록 후보 3개를 뽑는다(한 카테고리 몰림 방지). **각 후보에 출처 카테고리 + 지원 콘텐츠 유형 + 각 유형이 되는 근거를 함께 표시**한다.

출력 형식:
```
오늘의 주제 후보 (택1 해주세요)
① [AI관련] [주제] — 트렌드◎ 적합◎ 후킹◎
   지원유형: 의견대립◎(두 모델 견해 갈림) 거짓말○(사실확인 가능)
   출처: <검색으로 확인된 화제 근거 한 줄>
② [경제] [주제] — 트렌드◎ 적합◎ 후킹○
   지원유형: 거짓말·속도◎(전망 정확도 검증형)
   출처: <근거 한 줄>
③ [생활/문화] [주제] — 트렌드◎ 적합○ 후킹◎
   지원유형: 의견대립◎
   출처: <근거 한 줄>
```
→ **여기서 멈추고 사용자 선택을 기다린다.**

#### 콘텐츠 유형 판별 규칙 (주제가 어떤 유형을 성립시키는가)

- **거짓말·속도 비교**: 같은 질문에 정확도/속도를 겨룰 수 있어야 성립 (정답이 있는 사실형 질문).
- **오픈웨이트 vs 유료**: 비교 대상 중 하나가 오픈웨이트 모델이어야 성립.
- **모델 간 의견 대립**: 두 모델이 **상반된 답**을 낼 여지가 있어야 성립 (정답이 명확하면 대립이 안 생김 — 주로 견해·판단·창작형 질문).

**카테고리 → 유형 친화도** (후보 유형 태깅 시 참고, 절대 규칙 아님):
| 카테고리 | 잘 붙는 유형 |
|---|---|
| AI관련 | 오픈웨이트, 의견대립, 거짓말 (전부 가능) |
| 경제 | 거짓말·속도 (전망·수치 정확도 검증) |
| 사회 | 의견 대립 (견해 갈림) |
| 생활/문화 | 의견 대립 (취향·판단), 거짓말 (최신 밈 인지 여부) |
| IT/과학 | 오픈웨이트, 거짓말 (사실 정확도) |
| 세계 | 거짓말 (사실 확인), 의견 대립 |

한 주제가 여러 유형을 지원할 수 있고, 하나만 지원할 수도 있다. **지원하는 유형만** 이후 단계에서 만든다.

### STEP 2 · 포맷 선택 [스킬 추천 → 사용자 확정]

택한 주제의 **성격에 맞는 기본 포맷을 체크된 상태로** 제시한다. 사용자가 추가·제거·교체해 최종 확정한다.

**포맷 목록** (열린 리스트 — 툴이 늘면 항목 추가 가능):
- 글전용 (캡처 + 텍스트, 제작비 0) — 커뮤니티·스레드 직행
- 카드뉴스 (정적, 표지·본문·CTA) — 레비오사 카드뉴스
- 단일 이미지 (정적) — oowa
- 쇼츠 (동적, 15~30s) — gwanggo / XBRUSH
- UGC·데모 영상 (동적) — gwanggo Screen Demo / Founder

**추천 프리셋** (기본 체크 상태 — 강제 아님):

| 콘텐츠 유형 | 기본 체크(추천) | 이유 |
|---|---|---|
| 거짓말·속도 비교 | 쇼츠 + 글전용 | 틀린 답 걸리는 순간이 영상에서 임팩트 |
| 오픈웨이트 vs 유료 | 카드뉴스 + 글전용 | 수치·근거 정리라 캐러셀이 최적 |
| 모델 간 의견 대립 | 쇼츠 + 글전용 | "누구 편?" 투표 유도가 영상·스레드에서 잘 붙음 |

**항상 지키는 규칙:**
- 글전용은 어떤 경우에도 기본 체크(빼는 것도 사용자 자유지만 기본은 켜짐).
- 트렌드 점수가 매우 높은(=시의성 급한) 주제면 글전용을 우선 추천하고, 영상은 "타이밍 놓칠 수 있음" 경고와 함께 제시.

출력 형식:
```
[주제]에 추천하는 포맷입니다. 원하는 대로 켜고 끄세요.
  ☑ 쇼츠 (추천)
  ☑ 글전용 (추천)
  ☐ 카드뉴스
  ☐ 단일 이미지
  ☐ UGC·데모 영상
```
→ **여기서 멈추고 사용자 확정을 기다린다.**

### STEP 3 · 소재 붙여넣기 [수동]

확정된 (유형 × 포맷)에 필요한 aib.vote 결과/캡처를 사용자에게 요청한다.
- 어떤 앵글의 캡처가 필요한지 구체적으로 안내 (예: "거짓말 탭에서 A/B 정확도 결과 캡처", "의견 대립이면 두 모델의 상반된 답변 캡처").
- 여러 유형을 만들면 각 유형에 필요한 소재를 목록으로 정리해 한 번에 요청.
→ **여기서 멈추고 사용자 붙여넣기를 기다린다.**

### STEP 4 · 유형별 패키징 [되는 유형만]

붙여넣은 소재로 각 유형의 콘텐츠 골자를 만든다. 유형별 앵글·후킹:

- **거짓말·속도 비교** → 후킹: "어느 AI가 더 뻔뻔하게 거짓말할까?" / "속도 vs 정확도, 승자는?"
- **오픈웨이트 vs 유료** → 후킹: "무료 오픈모델이 유료를 이겼다" (데이터·근거 강조)
- **모델 간 의견 대립** → 후킹: "같은 질문, 정반대 답. 당신은 누구 편?" (투표 유도)

각 콘텐츠는 [후킹 → 비교 핵심 → 투표 CTA] 구조를 지킨다.

### STEP 5 · 채널별 변형 [포맷이 채널을 결정]

확정된 포맷에 따라 채널별 버전을 만든다. **포맷 → 채널 매핑:**

| 포맷 | 채널 | 톤·규칙 |
|---|---|---|
| 글전용 | 디시 인공지능 갤 · AI 네이버 카페 · 스레드/X | 논쟁 유도형, 드립 섞기 |
| 카드뉴스 | 인스타그램 · 네이버 카페 | 정보성, 표지·본문·CTA |
| 단일 이미지 | 스레드/X · 인스타 | 질문형 한 줄 + 이미지 1장 |
| 쇼츠 | 유튜브 쇼츠 · 릴스 · 틱톡 | 빠른 컷, 궁금증 유발 |
| UGC·데모 | 유튜브 · (아도바로로 영어권 확장) | 실사용 후기 톤 |

**채널별 카피 규칙** (레비오사 카피라이터로 생성 시 반영):
- X: 280자 이내
- Threads: 500자 이내
- LinkedIn: 3000자 이내
- 커뮤니티(디시/카페): 자극적 제목 + 짧은 본문 + 링크
- Reddit(오픈웨이트 유형·영어): 홍보 티 최소, 데이터 중심

**말투 [필수]: 모든 카피는 `references/voice.md`의 말투 프로필대로 작성한다.**
이것은 사용자 본인의 실제 글에서 추출한 스타일이다. 카피를 쓰기 전에 반드시 `references/voice.md`를 읽고, 그 채널별 톤(커뮤니티 존댓말 / 반말 익명 / 스레드 / X)과 공통 원칙(이모지·긴 대시·"~셈" 금지, 웃음은 ㅎㅎ, 짧은 문장, 오타 교정, AI 티 제거, 선택적 개인 사인)을 지킨다. 발행 전 voice.md 하단의 체크리스트로 자가 점검한다.

모든 채널 카피 끝에 `직접 투표해보기 → aib.vote` 링크(또는 UTM 포함 링크)를 삽입한다.

**숏폼 영상 배포 [필수]: 쇼츠·릴스 등 숏폼 영상이 결과물이면, `references/shortform_distribution.md`의 플랫폼별 표준 형식 그대로 문구를 뽑는다.**
이것은 실제 발행되어 검증된 형식이다. 각 플랫폼의 고정 규칙을 반드시 지킨다:
- **인스타 릴스는 4:5** (다른 플랫폼 9:16과 다름. 별도 리프레임 필요), 본문 + 태그 약 12개
- **스레드·X는 2단 구성** (훅+태그 게시물 / 풀본문·정보본문). 스레드는 반말+개인 사인, X는 2~3줄 끊기
- **유튜브**: 제목에 영문 태그(#claude #gemini 등), 설명은 존댓말 공통 본문 + 한글 태그
- **네이버 클립**: 줄바꿈 본문 + 한글 태그 약 5개
- **틱톡**: 콘셉트+영문태그+본문, **AI 생성 라벨 ON 필수**(게시 후 해제 불가)
- 존댓말 공통 본문 패턴: "[핵심요약]. 대표 AI [모델A], [모델B]도 예외는 아니네요~ AI 체험은 aib.vote"

### STEP 6 · 출력

최종 산출물을 한 묶음으로 정리:
1. **콘텐츠 세트** — (유형 × 채널)별 완성 카피 + 필요한 비주얼 제작 지시(어떤 툴·프롬프트로 만들지)
2. **캡션** — 채널별 글자수 규칙 반영
3. **숏폼 배포 세트** — 숏폼 영상이 있으면 `references/shortform_distribution.md` 형식으로 플랫폼별(인스타·스레드·X·유튜브·네이버클립·틱톡) 제목·본문·태그를 각각 출력. 인스타 4:5 / 나머지 9:16, 스레드·X 2단 구성, 틱톡 AI라벨 ON을 반영.
4. **aib.vote 링크** — 각 콘텐츠에 삽입 완료
5. **발행 전 사실확인 체크 [필수·고정 항목]** — 아래 참조. 반드시 출력에 포함한다.
6. **배포 일정 제안** — 글전용 즉시, 정적/동적은 제작 후 예약발행 시점 제안
7. **로테이션 메모** — 이번에 못 만든 콘텐츠 유형을 기록해, 다음 실행 때 우선 채우도록 안내

#### 발행 전 사실확인 체크 (매 실행 필수)

AI 답변에는 사실처럼 보이는 수치·주장이 자신 있게 담기지만, 그것이 맞다는 보장은 없다. 검증 안 된 수치를 콘텐츠로 퍼뜨리면 허위정보가 되고, 제품 신뢰(핵심 자산)를 해친다. 그래서 매 실행 출력 끝에 이 체크를 반드시 붙인다.

- **모델 답변 속 구체적 수치·고유명사·인과주장을 목록화**한다 (예: "2분기 영업이익 10조4400억", "전년比 1400%", "HBM 테스트 지연" 등).
- 각 항목에 대해 **콘텐츠가 그것을 '사실로 단정'했는지, '모델이 그렇게 답했다'로만 표현했는지** 표시한다.
- **원칙: 검증 전에는 사실로 단정하지 않는다.** "모델이 이렇게 자신 있게 답했다"(태도·현상)로 표현하고, 수치 자체를 콘텐츠의 사실 주장으로 쓰지 않는다.
- 발행 전 사용자에게 **실제 확인이 필요한 항목**을 한 줄로 정리해 알려준다 (가능하면 web_search로 핵심 수치 1~2개를 즉석 확인).
- 이 "자신 있다고 맞는 건 아니다"라는 관찰 자체가 향후 거짓말·속도 유형 콘텐츠의 좋은 소재가 됨을 메모로 남긴다.

## 톤·주의사항

- 커뮤니티용 카피는 자극적이되 **허위·과장 금지**. 비교 결과를 왜곡하지 않는다(제품 신뢰가 핵심 자산).
- 실존 인물·경쟁사를 비방하는 카피는 만들지 않는다. 비교는 모델 대 모델의 사실 기반으로.
- 비주얼 생성 시 크레딧 절약: 초기엔 무료/저크레딧 엔진(Z-Image Turbo, LTX 2.3 Free, oowa 기본)으로 테스트하고, 반응 좋은 포맷만 고급 엔진으로 승급.
- 저작권: 캡처·소재에 타사 로고·저작물이 크게 노출되면 사용자에게 확인.
